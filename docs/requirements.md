# dwPortal 需求（已锁定）

> 状态：已锁定（2026-07-29）

---

## 1. 一句话目标

做一个极简的家服索引门户，通过 `config.yaml` 管理服务列表，并根据访问来源（`dw.c` vs IP）提供不同的跳转地址。

## 2. MVP 范围

### 必须实现

- 后端能按路径优先级读取 `config.yaml`
- 修改 `config.yaml` 后，后端无需重启即可加载有效配置
- 后端提供 API 返回服务列表
- 前端请求 API 并渲染成可点击的按钮/卡片
- 实现「来源判断跳转」逻辑：
  - 请求来自 `dw.c`（或子域名）→ 跳转子域名形式（如 `oi.dw.c`）
  - 请求来自 IP → 跳转 `IP:端口` 形式
- 使用独立脚本只读解析 Caddyfile，并生成版本化服务目录
- 测试部署阶段支持脚本化安装、升级回滚、卸载和配置同步
- 测试部署的运行目录通过软链接读取仓库中的测试配置

### 不包含（MVP 阶段）

- 不写入、格式化或重载 Caddy 配置
- 不授予门户进程修改 Caddy 配置的权限
- 不做健康检查
- 不做复杂鉴权与 SSO
- 不追求视觉美观（留给后续阶段）

## 3. 配置路径优先级

后端读取 `config.yaml` 时按以下顺序查找：

1. 与二进制文件相同目录
2. 开发环境相对路径
3. 环境变量指定路径
4. 当前工作目录
